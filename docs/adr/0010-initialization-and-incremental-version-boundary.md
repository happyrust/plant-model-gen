# 初始化只固化当前态，数据版本从增量流程起版

项目初始化解析只读取一轮指纹稳定的源文件在初始化时的最新完整状态，并写入一次性 staging 数据目录；它不回放历史会话、不写数据版本锚点。新建站点默认从空目录启用 `versioned=true` 且 retention=`0`，因为该建库能力不能在首次增量时原地补开；解析、完整性校验和首次全量模型生成全部成功后才启用目录。首次全量模型生成仍发布可查询的 `model_gen` 起点锚点，因此首次增量前允许“模型基线可查、数据历史为空”的明确非对称状态。

数据历史只能由增量流程建立：初始化后尚无数据锚点的 dbnum，首次增量在应用变更前写一次 `source='incremental_baseline'` 的增量起版基线，随后再发布普通 `incremental` 提交，从而支持第一次变更的前后对比。存量 `source='full'` 锚点只读兼容，任何新写入都被禁止；已有 legacy full/incremental 历史的 dbnum 直接沿既有已提交锚点续跑，不回填伪造的 baseline。已有业务锚点的目录禁止原地初始化解析；新增 dbnum 必须走受锁的数据库增量接入，移除整个 dbnum 则新建目录重新初始化并切换。设计会话号和时间等信息由独立的会话元数据导入任务维护，不形成数据版本或模型提交。

初始化、增量、欠账追赶和修复入口必须在深层 seam 自持项目 mutation lock。多库增量任一数据提交失败时整轮跳过模型生成；数据已提交但对应欠账写入失败时沿 ADR-0006 保留数据并形成覆盖洞，同样不得进入本轮模型生成。数据提交和欠账均成功后，取本轮最后一个数据锚点的数据库时间作为统一 `VERSION AT` 读取时刻。模型无影响的增量发布 no-op `model_gen` 锚点。正式站点禁止任意 generate/regen，只有绑定既有数据锚点的受控 repair/catch-up 可以改写模型；同一 sesno 的最新成功修复仍属于原模型提交，但每次尝试必须追加不可变 `model_generation_run` 审计记录。

被否决的方案包括：解析期继续写 full 锚点、在已有历史的目录原地重解析、各 dbnum 使用不同模型读取时刻、部分数据提交失败后继续局部生成，以及无审计地覆盖同一 sesno 模型。这些方案都会重新引入未锚定写入、跨库撕裂或不可解释的版本结果。
